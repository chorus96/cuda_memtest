## 이번 세션의 큰 그림 — "여럿이 동시에 하나를 건드릴 때"

세션 3에서 본 Test 10은 210만 스레드가 동시에 메모리를 검사합니다. 오류를 발견한 스레드들은 모두
**같은 카운터 하나**(`err_count`)를 늘리려 합니다. 이때 그냥 `err_count++`를 쓰면 값이 사라집니다.
이것이 **경쟁 조건(race condition)** 이고, 이를 막는 것이 **원자연산(atomic operation)** 입니다.

또한 커널은 **비동기(asynchronous)** 로 실행되므로, 오류가 나도 CPU는 바로 알지 못합니다.
이 저장소는 `CUERR` / `SYNC_CUERR_KERNEL` 매크로로 모든 CUDA 호출을 감싸 오류를 즉시 잡아냅니다.

### 오늘의 두 주인공 매크로

```c
// (1) RECORD_ERR — 오류를 안전하게 세고 기록한다  (tests.cpp:76)
#define RECORD_ERR(err, p, expect, current) do{        \
    unsigned int idx = atomicAdd(err, 1);              \  // ★ 원자적으로 +1, 이전 값을 반환
    idx = idx % MAX_ERR_RECORD_COUNT;                  \  // 최근 10개만 순환 기록
    err_addr[idx]        = (unsigned long)p;           \  // 오류가 난 주소
    err_expect[idx]      = (unsigned long)expect;      \  // 기대했던 값
    err_current[idx]     = (unsigned long)current;     \  // 실제로 읽은 값
    err_second_read[idx] = (unsigned long)(*p);        \  // 다시 읽은 값
}while(0)
```

```c
// (2) SYNC_CUERR_KERNEL — 커널을 실행하고, 동기화 후 오류를 검사한다  (cuda_memtest.h:138)
#define SYNC_CUERR_KERNEL(...)  do{ apiError_t cuda_err; \
    __VA_ARGS__;                                        \  // 커널 실행
    cuda_err = cudaDeviceSynchronize();                \  // ★ GPU가 끝날 때까지 대기
    if (cuda_err != cudaSuccess) {                     \  // 오류면 파일·줄과 함께 출력 후 종료
        FPRINTF("ERROR: CUDA error: %s, line %d, file %s\n", ...);  \
        exit(cuda_err); }}while(0)
```

## Exercise 1 — atomicAdd가 왜 필요한가 (경쟁 조건 재현)

**① 목표**: 원자연산을 일반 덧셈으로 바꾸면 카운트가 어떻게 틀어지는지 직접 본다.

**② 코드**: `RECORD_ERR` 매크로(`tests.cpp:76`)의 `atomicAdd`를 **일반 증가로 바꿔** 경쟁 조건을 만듭니다.

```c
#define RECORD_ERR(err, p, expect, current) do{        \
    /* 원본: unsigned int idx = atomicAdd(err, 1);  */ \
    unsigned int idx = (*err);   /* Exercise 1: 비원자적 읽기 */ \
    (*err) = (*err) + 1;         /* Exercise 1: 비원자적 증가 */ \
    idx = idx % MAX_ERR_RECORD_COUNT;                  \
    err_addr[idx] = (unsigned long)p;                  \
    err_expect[idx] = (unsigned long)expect;           \
    err_current[idx] = (unsigned long)current;         \
    err_second_read[idx] = (unsigned long)(*p);        \
}while(0)
```

이제 **모든 메모리 위치에서 오류가 나도록** 세션 2의 fault injection을 재사용합니다. `kernel_move_inv_read`
(`tests.cpp:285`)에서 검사 직전에 값을 항상 훼손:

```c
    for (i = 0; i < BLOCKSIZE/sizeof(unsigned int); i++){
        ptr[i] = ~pattern;          // Exercise 1: 모든 값을 일부러 틀리게
        if (ptr[i] != pattern){
            RECORD_ERR(err, &ptr[i], pattern, ptr[i]);
        }
    }
```

**③ 실행**:
```bash
make -j
./cuda_memtest --disable_all --enable_test 2 --num_passes 1 2>&1 | grep -i "errors found"
```

**④ 관찰**: 보고된 오류 개수가 **실제 훼손한 개수보다 적게** 나오는지 확인. (여러 스레드가 동시에
같은 값을 읽고 각자 +1 하면서 증가가 "먹힙니다".) 원본(`atomicAdd`)으로 되돌려 다시 실행하면
개수가 안정적으로 나옵니다.

**⑤ 생각해보기**: 왜 비원자적 `(*err) = (*err) + 1`이 값을 잃을까? "읽기 → 더하기 → 쓰기" 세 단계
사이에 다른 스레드가 끼어들면 어떻게 되는지 그림으로 그려보세요.

> **반드시 원복**: `RECORD_ERR`의 `atomicAdd`와 fault injection을 원래대로 되돌리세요.

## Exercise 2 — atomicAdd의 반환값이 인덱스가 되는 원리

**① 목표**: `atomicAdd(err, 1)`이 **이전 값을 반환**한다는 사실과, 그 값이 어떻게 고유 슬롯 번호가 되는지 이해한다.

**② 코드**: `RECORD_ERR`에 반환된 `idx`를 출력하는 디버그 문을 추가(원자 버전 유지):

```c
#define RECORD_ERR(err, p, expect, current) do{        \
    unsigned int idx = atomicAdd(err, 1);              \
    printf("[GPU] atomicAdd 반환 idx=%u (슬롯 %u)\n", idx, idx % MAX_ERR_RECORD_COUNT); \
    idx = idx % MAX_ERR_RECORD_COUNT;                  \
    err_addr[idx] = (unsigned long)p;                  \
    /* ... 나머지 동일 ... */                           \
    err_second_read[idx] = (unsigned long)(*p);        \
}while(0)
```

fault injection으로 소수의 오류만 만들어 관찰(세션 2 Ex 3 방식 — 첫 블록 첫 값만 훼손 권장).

**③ 실행**:
```bash
make -j
./cuda_memtest --disable_all --enable_test 2 --num_passes 1 2>&1 | grep atomicAdd | head
```

**④ 관찰**: `idx`가 0, 1, 2, ... 처럼 **겹치지 않는 고유 번호**로 나오는지 확인. 여러 스레드가 동시에
호출해도 `atomicAdd`가 서로 다른 반환값을 보장합니다.

**⑤ 생각해보기**: `idx % MAX_ERR_RECORD_COUNT`(=10)를 하는 이유는? 오류가 100만 개여도 배열은 10칸뿐이라
**최근 10개만 순환 저장**합니다. 왜 전부 저장하지 않을까?(메모리·성능)

> **원복**: 추가한 `printf`를 삭제하세요.

## Exercise 3 — CUERR 매크로가 오류를 잡는 순간

**① 목표**: 잘못된 CUDA 호출을 `CUERR`가 어떻게 **파일명·줄 번호와 함께** 잡아 종료시키는지 본다.

**② 코드**: `CUERR`(`cuda_memtest.h:132`)는 CUDA 호출을 감싸 실패 시 메시지를 찍고 `exit`합니다.
`error_checking`의 첫 `cudaMemcpy`(`tests.cpp:117`)에 **일부러 잘못된 크기**를 줍니다.

```c
    // 원본: sizeof(unsigned int)
    CUERR(MEMTEST_API_PREFIX(Memcpy)((void*)&err, (void*)err_count,
          999999999,    // Exercise 3: 말도 안 되는 큰 크기 → 오류 유발
          MEMTEST_API_PREFIX(MemcpyDeviceToHost)));
```

**③ 실행**:
```bash
make -j
./cuda_memtest --disable_all --enable_test 2 --num_passes 1
```

**④ 관찰**: 다음과 같은 형식의 메시지가 뜨는지 확인:
```
ERROR: CUDA error: <오류 설명>, line <숫자>, file tests.cpp
```
`__LINE__`, `__FILE__` 덕분에 **어디서 터졌는지** 즉시 알 수 있습니다.

**⑤ 생각해보기**: 만약 `CUERR` 없이 그냥 `cudaMemcpy(...)`를 호출했다면? CUDA 호출은 실패해도 조용히
오류 코드만 반환합니다. 확인하지 않으면 프로그램은 잘못된 상태로 계속 진행합니다. 그래서 실전 코드는
**모든 CUDA 호출을 CUERR로 감쌉니다**.

> **반드시 원복**: 크기를 `sizeof(unsigned int)`로 되돌리세요.

## Exercise 4 — 비동기 오류와 DeviceSynchronize

**① 목표**: 커널은 비동기 실행이라, 동기화(synchronize) 전에는 커널 오류를 알 수 없다는 것을 이해한다.

**② 코드**: `SYNC_CUERR_KERNEL`(`cuda_memtest.h:138`)은 커널 실행 **직후 `cudaDeviceSynchronize`** 로
GPU 완료를 기다린 뒤 오류를 검사합니다. 세션 1 Ex 4(경계 검사 제거)를 재사용해 커널에서 잘못된 접근을 만듭니다.

`kernel_move_inv_write`(`tests.cpp:245`)의 경계 검사를 주석 처리:

```c
    // if (ptr >= (unsigned int*) end_ptr) {   // Exercise 4: guard 제거
    //     return;
    // }
```

**③ 실행**:
```bash
make -j
./cuda_memtest --disable_all --enable_test 2 --num_passes 1
```

**④ 관찰**:
- `SYNC_CUERR_KERNEL`이 `cudaDeviceSynchronize` 반환값을 검사해 `illegal memory access` 류 오류를
  **커널 실행 줄과 함께** 보고하는지 확인.
- 오류 메시지의 `line`이 `move_inv_test`의 커널 실행 지점(`tests.cpp:315` 부근)을 가리키는지 보세요.

**⑤ 생각해보기**: 커널 실행(`<<<>>>`) 그 자체는 오류를 반환하지 않습니다. 실제 잘못된 메모리 접근은
GPU에서 **나중에** 일어나기 때문입니다. `cudaDeviceSynchronize`로 "GPU가 다 끝날 때까지 기다린 후"
검사해야 이런 오류를 잡을 수 있습니다. 이것이 세션 3의 "커널은 비동기"와 직접 연결됩니다.

> **반드시 원복**: 경계 검사 주석을 해제하세요.
