## 이번 세션의 큰 그림 — 같은 문제, 두 개의 커널

지금까지 본 Test 0~9는 **블록당 스레드 1개**(`<<<grid, 1>>>`)로 GPU를 거의 놀렸습니다. 의도된 단순함이었죠.
Test 10은 **정반대**입니다. 같은 "메모리에 쓰고 읽어 검사한다"를 **수백만 스레드**로 병렬화합니다.

```c
// tests.cpp:1488
#define STRESS_BLOCKSIZE 64          // 블록당 스레드 64개
#define STRESS_GRIDSIZE  (1024*32)   // 블록 32,768개
// → 총 스레드 = 64 × 32,768 = 2,097,152 개 (약 210만)
```

```c
// test10  (tests.cpp:1491)
dim3 gridDim(STRESS_GRIDSIZE);
dim3 blockDim(STRESS_BLOCKSIZE);
test10_kernel_write<<<gridDim, blockDim, 0, stream>>>(ptr, tot_num_blocks*BLOCKSIZE, p1);  // tests.cpp:1513
```

세션 1의 `<<<128, 1>>>`(스레드 128개)과 비교하면 **1만 6천 배** 많은 스레드입니다.

### 스레드가 자기 몫을 계산하는 법 (grid-stride 스타일)

```c
// test10_kernel_write  (tests.cpp:1424)
int avenumber = memsize/(gridDim.x*gridDim.y);   // 블록 하나가 맡을 바이트 수
TYPE* mybuf = (TYPE*)(ptr + blockIdx.x*avenumber);  // 이 블록의 시작 위치
int n = avenumber/(blockDim.x*sizeof(TYPE));     // 스레드 하나가 반복할 횟수
for (i = 0; i < n; i++){
    int index = i*blockDim.x + threadIdx.x;      // ★ 이웃 스레드가 이웃 주소를
    mybuf[index] = p1;
}
```

여기서 처음으로 **`threadIdx.x`와 `blockDim.x`가 등장**합니다. 세션 1의 커널에는 없었죠(스레드가 1개였으니까).
`index = i*blockDim.x + threadIdx.x`는 **이웃한 스레드가 이웃한 메모리 주소**를 접근하게 만드는 핵심 패턴입니다.
이것을 **메모리 병합(coalescing)** 이라 하며, GPU 대역폭을 최대로 끌어냅니다.

## Exercise 2 — 대역폭(bandwidth)을 눈으로 보기

**① 목표**: Test 10이 스스로 계산해 출력하는 대역폭(GB/s) 로그를 확인한다.

**② 코드**: Test 10은 CUDA 이벤트(event)로 시간을 재고 대역폭을 계산합니다.

```c
// test10  (tests.cpp:1510~1525)
cudaEventRecord(start, stream);
test10_kernel_write<<<...>>>(...);
for (i=0; i<n; i++) test10_kernel_readwrite<<<...>>>(...);
cudaEventRecord(stop, stream);
cudaEventSynchronize(stop);
cudaEventElapsedTime(&elapsedtime, start, stop);   // 밀리초 단위 경과 시간
DEBUG_PRINTF("test10: elapsedtime=%f, bandwidth=%f GB/s\n",
             elapsedtime, (2*n+1)*tot_num_blocks/elapsedtime);
```

대역폭 공식 해석: 쓰기 1회 + 읽고쓰기 n회(각 읽기+쓰기 2회 접근) = `(2n+1)` 패스.
`tot_num_blocks`는 MB 단위이므로 `MB/ms = GB/s`가 됩니다.

**③ 실행**: `--verbose`를 주어야 `DEBUG_PRINTF`가 출력됩니다.

```bash
./cuda_memtest --disable_all --enable_test 10 --num_iterations 50 --num_passes 1 --verbose
```

**④ 관찰**: `test10: elapsedtime=... , bandwidth=... GB/s` 로그의 대역폭 값을 기록.
`nvidia-smi -q` 또는 GPU 스펙표의 이론 대역폭과 비교해 보세요(보통 이론치의 60~90%).

**⑤ 생각해보기**: 왜 이벤트(event)로 시간을 잴까? `gettimeofday` 같은 CPU 타이머 대신 GPU 이벤트를 쓰는
이유는? (커널은 비동기 실행 → GPU 타임라인에서 재야 정확)

## Exercise 4 — 메모리 병합(coalescing) 깨뜨리기

**① 목표**: 이웃 스레드가 이웃 주소를 접근할 때 왜 빠른지, 그 접근을 흩뜨리면 얼마나 느려지는지 본다.

**② 코드**: `test10_kernel_write`(`tests.cpp:1424`)의 인덱스 계산을 일부러 "비병합" 방식으로 바꿉니다.

```c
    for(i=0;i < n;i++){
        // 원본 (병합됨): 이웃 스레드가 이웃 주소
        // int index = i*blockDim.x + threadIdx.x;

        // === Exercise 4: 비병합으로 변경 (스레드마다 멀리 떨어진 주소) ===
        int index = threadIdx.x*n + i;
        // === 여기까지 ===
        mybuf[index]= p1;
    }
```

> 같은 방식으로 `test10_kernel_readwrite`(`tests.cpp:1443`)의 인덱스도 바꿔야 정확히 비교됩니다.
> (검사 로직이 어긋나 오류가 잔뜩 보고될 수 있는데, 이번 실습에서는 **대역폭 수치에만** 주목하세요.)

**③ 실행**:

```bash
make -j
./cuda_memtest --disable_all --enable_test 10 --num_iterations 50 --num_passes 1 --verbose 2>&1 | grep bandwidth
```

**④ 관찰**: 대역폭이 원본 대비 얼마나 떨어졌는가? (보통 몇 배 느려집니다.)

**⑤ 생각해보기**: 하드웨어는 인접한 스레드들의 메모리 요청을 하나의 큰 전송으로 묶습니다(병합). 접근을
흩뜨리면 이 묶음이 깨져 작은 전송이 많아지고 대역폭이 급락합니다. 이것이 CUDA 성능 최적화의 1순위 원칙입니다.

> **반드시 원복**: Exercise 4의 인덱스 변경을 원래대로 되돌리세요.
