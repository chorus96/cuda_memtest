# CUDA 세미나 커리큘럼 — `cuda_memtest`로 배우는 실전 GPU 프로그래밍

> **대상**: C 언어는 알지만 CUDA는 처음인 입문자
> **교재**: 이 저장소(`cuda_memtest`)의 실제 소스 코드
> **형식**: 다회차 시리즈 (세션 0 ~ 세션 5, 회차당 90~120분)
> **언어 표기**: 한글 용어 옆에 원어(영어)를 병기합니다. 예) 커널(kernel)

---

## 0. 이 세미나의 설계 철학

대부분의 CUDA 입문 강의는 `vectorAdd` 같은 장난감 예제로 시작해서 실무 코드로 넘어갈 때 벽에 부딪힙니다.
이 세미나는 **처음부터 실제로 동작하는 500줄 이상의 프로덕션 코드**(`cuda_memtest`)를 교재로 삼습니다.

`cuda_memtest`가 입문 교재로 뛰어난 이유:

1. **주제가 명확하다** — "GPU 메모리에 값을 쓰고, 다시 읽어서, 같은지 비교한다." 이 한 문장이 전부입니다.
   알고리즘이 단순하므로 학습자는 CUDA 문법 자체에 집중할 수 있습니다.
2. **두 가지 상반된 커널 스타일이 한 저장소에 있다**:
   - **Test 0~9** — `<<<grid, 1>>>` : 블록당 스레드 1개. 의도적으로 단순한 "느린" 코드. → CUDA 입문에 최적
   - **Test 10** — `<<<32768, 64>>>` : 대역폭 최적화된 "빠른" 코드. → 최적화 수업의 완벽한 대조군
   - 같은 문제를 두 방식으로 푸는 코드를 나란히 읽으며 **왜** 최적화가 필요한지 체감합니다.
3. **실무 요소가 모두 들어 있다** — 원자연산(atomic), 에러 핸들링 매크로, CUDA 이벤트 타이밍,
   호스트-디바이스 전송, 멀티 GPU 스레딩, HIP 이식성까지.
4. **하드웨어를 직접 만진다** — 추상적인 계산이 아니라 실제 GPU 메모리의 물리적 오류를 찾는 코드입니다.
   결과가 눈에 보이므로 동기 부여가 강합니다.

## 세션 0 — 환경 구축과 큰 그림 (90분)

**학습 목표**
- GPU가 CPU와 무엇이 다른지(처리량 vs 지연시간) 한 문장으로 설명할 수 있다.
- `cuda_memtest`를 직접 빌드하고 실행할 수 있다.
- 이 도구가 무엇을 하는 프로그램인지 설명할 수 있다.

**강의 내용**
1. GPU 컴퓨팅이란: SIMT(Single Instruction, Multiple Threads) 모델, 수천 개 코어의 의미
2. CPU와 GPU의 분업: 호스트(host, CPU) ↔ 디바이스(device, GPU)
3. `cuda_memtest`가 푸는 문제: GPU 메모리의 하드 오류(hard error)와 소프트 오류(soft error) — `doc/` 논문 배경
4. 빌드 시스템 이해: `CMakeLists.txt`, `CMAKE_CUDA_ARCHITECTURES`, CUDA vs HIP 백엔드

**코드 리딩**: `README.md`의 빌드 절차, `CMakeLists.txt` 상단, `main()`의 GPU 개수 확인(`cuda_memtest.cpp:299`)

**실습 랩 (Lab 0)**
- `cmake -DCMAKE_CUDA_ARCHITECTURES=<본인 GPU> ..` → `make`
- `./cuda_memtest --list_tests` 로 11개 테스트 확인
- `./cuda_memtest --stress --num_iterations 100 --num_passes 1` 로 빠른 실행
- `nvidia-smi`로 GPU 사용률 관찰

> **환경이 없는 참석자 대비**: GPU가 없는 참석자는 Google Colab(무료 GPU) 또는 클라우드 인스턴스로 대체.
> 강사는 실행 로그를 미리 캡처해 두어 오프라인에서도 결과를 보여줄 수 있게 준비.

## 세션 1 — CUDA 스레드 모델과 첫 커널 (120분) ★ 핵심 회차

**학습 목표**
- `__global__` 함수(커널)가 일반 C 함수와 무엇이 다른지 설명할 수 있다.
- `<<<grid, block>>>` 실행 구성(execution configuration)의 의미를 안다.
- `blockIdx`, `threadIdx`, `blockDim`, `gridDim`으로 스레드가 자기 데이터를 찾는 원리를 안다.
- `kernel_move_inv_write`를 한 줄씩 설명할 수 있다.

**강의 내용**
1. 커널(kernel)이란: `__global__` 한정자, CPU에서 호출하고 GPU에서 실행
2. 실행 구성 `<<<gridDim, blockDim>>>`: 블록(block)의 격자(grid), 블록 안의 스레드(thread)
3. 내장 변수(built-in variables): `blockIdx`, `threadIdx`, `blockDim`, `gridDim`
4. 이 저장소의 인덱싱 관례: `_ptr + blockIdx.x * BLOCKSIZE` → **블록 하나가 메모리 1 MB를 담당**
5. `<<<grid, 1>>>`의 의미: 블록당 스레드 1개 — 왜 이렇게 단순하게 짰나? (주소 배선 테스트 목적)

**코드 리딩** (`tests.cpp`)
- `kernel_move_inv_write` (`tests.cpp:245`) — 가장 단순한 커널부터
- `move_inv_test` 호스트 함수 (`tests.cpp:304`) — 커널을 어떻게 반복 실행하는가
- 매크로 `BLOCKSIZE`, `GRIDSIZE` (`cuda_memtest.h:91`)

**실습 랩 (Lab 1)**: 세션 1 실습 가이드 참고 — 첫 커널 수정, 스레드 인덱스 출력, 그리드 크기 실험

## 세션 2 — 메모리 모델과 데이터 이동 (120분)

**학습 목표**
- GPU 전역 메모리(global memory)를 할당·해제·전송하는 3종 API를 쓸 수 있다.
- "쓰기 커널 종료 → 읽기 커널 시작" 패턴이 왜 필요한지(메모리 플러시) 설명할 수 있다.
- 이동 반전(moving inversion) 알고리즘을 커널 3개의 협업으로 이해한다.

**강의 내용**
1. GPU 메모리 계층: 전역(global) / 공유(shared) / 레지스터(register) 개요
2. 호스트-디바이스 데이터 이동: `cudaMalloc`, `cudaMemcpy`, `cudaMemset`
   - 실제 사용처: 오류 기록을 CPU로 가져오는 `error_checking` (`tests.cpp:117`)
3. 메모리 할당 전략: 가능한 만큼 할당하고 실패하면 줄이는 로직 (`cuda_memtest.cpp:157`)
4. **왜 커널을 세 번 나눠 실행하나**: 쓰기 → (커널 종료로 메모리 반영) → 읽기·검사 → 보수 쓰기 → 재검사
   - `move_inv_test`의 3-루프 구조 (`tests.cpp:312`, `320`, `328`)
5. 이동 반전(moving inversion) 알고리즘의 원리: p1 기록 → p1 확인·p2 기록 → p2 확인

**코드 리딩**: `kernel_move_inv_readwrite`(`tests.cpp:262`), `kernel_move_inv_read`(`tests.cpp:284`), `error_checking`(`tests.cpp:107`)

**실습 랩 (Lab 2)**: 패턴 값 바꿔보기, 일부러 메모리 값을 훼손시켜 오류 검출 재현, `cudaMemcpy` 방향 실험

## 세션 3 — 병렬성 설계와 성능 (120분)

**학습 목표**
- `<<<grid, 1>>>`(느림)과 `<<<32K, 64>>>`(빠름)의 성능 차이를 설명할 수 있다.
- 그리드 스트라이드(grid-stride) 방식으로 스레드가 여러 원소를 처리하는 패턴을 안다.
- CUDA 이벤트(event)로 커널 시간을 측정하고 대역폭(bandwidth)을 계산할 수 있다.
- 메모리 접근 병합(coalescing)의 개념을 안다.

**강의 내용**
1. Test 0~9의 한계: 블록당 스레드 1개 → GPU의 병렬성을 거의 못 씀 (의도된 단순함)
2. Test 10의 설계: `STRESS_BLOCKSIZE 64`, `STRESS_GRIDSIZE 32768` (`tests.cpp:1488`)
3. 스레드가 자기 몫을 계산하는 법: `avenumber`, `index = i*blockDim.x + threadIdx.x` (`tests.cpp:1424`)
4. 메모리 병합(memory coalescing): 인접 스레드가 인접 주소를 읽을 때 왜 빠른가
5. CUDA 이벤트 타이밍: `cudaEventRecord` / `cudaEventElapsedTime`, 대역폭 계산식 (`tests.cpp:1510`, `1525`)
6. 스트림(stream) 맛보기: `test10_kernel_write<<<..., stream>>>` (`tests.cpp:1513`)

**코드 리딩**: `test10_kernel_write`(`tests.cpp:1424`), `test10_kernel_readwrite`(`tests.cpp:1443`), `test10`(`tests.cpp:1491`)

**실습 랩 (Lab 3)**: `STRESS_BLOCKSIZE`/`STRESS_GRIDSIZE`를 바꿔가며 대역폭 측정, Test 3 vs Test 10 실행 시간 비교

## 세션 4 — 원자연산과 에러 핸들링 (120분)

**학습 목표**
- 여러 스레드가 동시에 하나의 카운터를 늘릴 때 왜 원자연산이 필요한지 안다.
- `atomicAdd`와 `RECORD_ERR` 매크로의 동작을 설명할 수 있다.
- CUDA API 오류를 잡는 `CUERR` 매크로의 필요성과 구조를 안다.
- 커널 실행 후 `cudaDeviceSynchronize`가 왜 오류 검출에 필수인지 안다.

**강의 내용**
1. 경쟁 조건(race condition): 여러 스레드가 `err_count++`를 동시에 하면?
2. 원자연산(atomic operation): `atomicAdd(err, 1)`이 반환하는 인덱스로 안전하게 기록 (`tests.cpp:76`)
3. `RECORD_ERR` 매크로 해부: 오류 주소·기대값·실제값·재읽기값 저장
4. 비동기 오류의 함정: 커널은 비동기 실행 → `DeviceSynchronize` 후에야 오류를 안다 (`cuda_memtest.h:138`)
5. `CUERR` / `SYNC_CUERR_KERNEL` 매크로: 모든 CUDA 호출을 감싸 파일·줄 번호와 함께 오류 출력
6. 방어적 프로그래밍: 실제 프로덕션 코드의 오류 처리 관례

**코드 리딩**: `RECORD_ERR`(`tests.cpp:76`), `CUERR`·`SYNC_CUERR_KERNEL`(`cuda_memtest.h:132`), `error_checking`(`tests.cpp:107`)

**실습 랩 (Lab 4)**: 일부러 CUDA 오류를 유발해 `CUERR` 메시지 관찰, `atomicAdd`를 일반 `++`로 바꿔 경쟁 조건 재현

## 세션 5 — 멀티 GPU · 이식성 · 미니 프로젝트 (120분)

**학습 목표**
- CPU 스레드 하나가 GPU 하나를 맡는 멀티 GPU 패턴을 이해한다.
- 하나의 코드가 CUDA와 HIP(AMD) 양쪽에서 빌드되는 추상화 기법을 안다.
- 배운 것을 종합해 **자신만의 메모리 테스트 커널**을 작성한다.

**강의 내용**
1. 멀티 GPU: `pthread_create`로 GPU마다 스레드, 각 스레드가 `cudaSetDevice` (`cuda_memtest.cpp:136`, `541`)
2. 스레드 지역 저장소(thread-local): `__thread unsigned int gpu_idx` (`cuda_memtest.h:81`)
3. 이식성 추상화: `MEMTEST_API_PREFIX(name)` 매크로로 `cuda*`/`hip*` 통일 (`cuda_memtest.h:62`)
4. 코드 구조 종합 복습: `main` → `thread_func` → `run_tests` → 각 테스트 커널

**미니 프로젝트 (Capstone)**
참석자는 다음 중 하나를 골라 구현·발표:
- (A) **새 패턴 테스트**: 체커보드(0xAAAA/0x5555 교차) 패턴 커널을 새 Test로 추가
- (B) **성능 개선**: Test 3(느린 커널)을 Test 10 스타일로 다시 짜서 대역폭 향상 측정
- (C) **관찰 도구**: 오류 발생 주소의 비트 패턴을 히스토그램으로 출력하는 기능 추가

**코드 리딩**: `thread_func`(`cuda_memtest.cpp:122`), `cuda_memtests[]` 테스트 등록 배열(`tests.cpp:1555`)
