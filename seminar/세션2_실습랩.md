## 이번 세션의 큰 그림 — "쓰고, 끝내고, 읽어서, 검사한다"

세션 1의 쓰기 커널은 이야기의 절반이었습니다. 세션 2는 나머지 절반, 즉 **읽어서 검사하기**와
**GPU ↔ CPU 데이터 이동**을 다룹니다. 핵심은 `move_inv_test`의 **세 개의 for 루프**입니다.

```c
// move_inv_test  (tests.cpp:305)
// 1) 쓰기 루프 : 전체 메모리에 p1을 쓴다
for (i=0; i<tot_num_blocks; i+=GRIDSIZE)
    kernel_move_inv_write<<<grid,1>>>(...p1);          // tests.cpp:315

// 2) 읽고-쓰기 루프 : p1인지 검사하고, p2(보수)를 쓴다
for (i=0; i<tot_num_blocks; i+=GRIDSIZE) {
    kernel_move_inv_readwrite<<<grid,1>>>(...p1, p2...); // tests.cpp:323
    err += error_checking("move_inv_readwrite", i);      // 오류를 CPU로 가져옴
}

// 3) 읽기 루프 : p2인지 다시 검사한다
for (i=0; i<tot_num_blocks; i+=GRIDSIZE) {
    kernel_move_inv_read<<<grid,1>>>(...p2...);           // tests.cpp:331
    err += error_checking("move_inv_read", i);
}
```

**왜 루프를 3개로 나누고, 커널을 매번 종료시킬까?**
쓰기 커널이 **완전히 끝나야** 그 결과가 메모리에 확실히 반영(flush)됩니다. 같은 커널 안에서 쓰고 바로 읽으면,
아직 메모리에 반영되지 않은 값을 읽을 수 있습니다. 그래서 **쓰기 커널 종료 → 읽기 커널 시작**으로 분리합니다.
이것이 이 도구가 하드웨어 메모리 오류를 신뢰성 있게 잡아내는 핵심 설계입니다.

이동 반전(moving inversion): `p1`을 썼다가 → `p1` 확인 후 보수 `p2 = ~p1`를 쓰고 → `p2` 확인.
비트를 뒤집어 가며 검사하므로 "1로 고착" · "0으로 고착"된 불량 비트를 모두 잡습니다.

## Exercise 2 — 오류는 어떻게 CPU로 돌아오나 (cudaMemcpy 관찰)

**① 목표**: GPU가 기록한 오류 정보를 CPU가 `cudaMemcpy`로 가져오는 과정을 이해한다.

**② 코드**: `error_checking`(`tests.cpp:108`)의 맨 앞에서 실제로 복사가 일어납니다.

```c
// tests.cpp:117 — GPU의 err_count(디바이스 메모리)를 CPU 변수 err로 복사
CUERR(MEMTEST_API_PREFIX(Memcpy)((void*)&err, (void*)err_count,
      sizeof(unsigned int), MEMTEST_API_PREFIX(MemcpyDeviceToHost)));
```

`err_count`는 GPU에 있는 카운터입니다(디바이스 포인터). CPU는 그 값을 직접 읽을 수 없으므로
**반드시 `cudaMemcpy`로 복사**해야 합니다. 복사 방향은 `...DeviceToHost` (GPU→CPU).

확인용 출력을 추가합니다(복사 직후):

```c
    CUERR(MEMTEST_API_PREFIX(Memcpy)((void*)&err, (void*)err_count,
          sizeof(unsigned int), MEMTEST_API_PREFIX(MemcpyDeviceToHost)));

    // === Exercise 2: 추가 ===
    if (err > 0) {
        fprintf(stderr, "[CPU] GPU에서 가져온 오류 개수 err_count = %u\n", err);
    }
    // === 여기까지 ===
```

**③ 실행**: `make -j` 후 — 정상 GPU라면 오류가 0이라 출력이 안 보일 수 있습니다. 다음 실습(Ex 3)에서
일부러 오류를 만들어 이 경로를 발동시킵니다.

**④ 관찰**: Ex 3까지 마친 뒤 이 메시지가 출력되는지 확인.

**⑤ 생각해보기**: `err_count`를 `cudaMemcpy` 없이 CPU에서 `*err_count`로 바로 읽으면 어떻게 될까?
(디바이스 포인터를 호스트에서 역참조 → 오류)

## Exercise 3 — 일부러 메모리를 훼손해 오류 검출 재현 (fault injection)

**① 목표**: 검사 커널이 "기대값과 다른 값"을 실제로 잡아내는 것을 눈으로 확인한다.

**② 코드**: 읽기 커널 `kernel_move_inv_read`(`tests.cpp:285`)에서, 검사 **직전에** 첫 블록의 첫 값을
일부러 틀리게 바꿉니다.

```c
    for (i = 0; i < BLOCKSIZE/sizeof(unsigned int); i++){
        // === Exercise 3: 일부러 오류 주입 ===
        if (blockIdx.x == 0 && i == 0) {
            ptr[0] = ptr[0] ^ 0x1;      // 최하위 비트 하나를 뒤집어 훼손
        }
        // === 여기까지 ===
        if (ptr[i] != pattern){
            RECORD_ERR(err, &ptr[i], pattern, ptr[i]);
        }
    }
```

**③ 실행**:
```bash
make -j
./cuda_memtest --disable_all --enable_test 2 --num_passes 1
```

**④ 관찰**:
- Ex 2에서 추가한 `[CPU] ... err_count = ...` 메시지가 뜨는가?
- `error_checking`이 출력하는 `ERROR: ... errors found in block 0`, 그리고 기대값·현재값·차이(diff)가 보이는가?
- `diff`가 `0x1`(우리가 뒤집은 비트)인지 확인.

**⑤ 생각해보기**: 이것이 바로 실제 불량 GPU 메모리에서 일어나는 일입니다. 우리는 소프트웨어로 오류를
"주입"했지만, 진짜 불량 칩은 하드웨어적으로 같은 증상을 냅니다. `error_checking`은 오류 주소·기대값·실제값을
기록해 어떤 비트가 고장 났는지 알려줍니다.

## Exercise 4 — 디바이스 오류 버퍼는 어디서 할당되나 (cudaMalloc + cudaMemset)

**① 목표**: 오류 기록용 GPU 버퍼가 `cudaMalloc`으로 만들어지고 `cudaMemset`으로 0 초기화되는 것을 본다.

**② 코드**: `allocate_small_mem`(`tests.cpp:1573`)이 프로그램 시작 시 이 버퍼들을 만듭니다.

```c
// tests.cpp:1573
allocate_small_mem(void) {
    CUERR(MEMTEST_API_PREFIX(Malloc)((void**)&err_count, sizeof(unsigned int)));   // GPU에 4바이트 할당
    CUERR(MEMTEST_API_PREFIX(Memset)(err_count, 0, sizeof(unsigned int)));         // 0으로 초기화
    CUERR(MEMTEST_API_PREFIX(Malloc)((void**)&err_addr,  sizeof(unsigned long)*MAX_ERR_RECORD_COUNT));
    CUERR(MEMTEST_API_PREFIX(Memset)(err_addr, 0, sizeof(unsigned long)*MAX_ERR_RECORD_COUNT));
    // ... err_expect, err_current, err_second_read 도 동일 패턴
}
```

메모리 3종 API를 여기서 모두 볼 수 있습니다:
- `cudaMalloc((void**)&포인터, 바이트수)` — GPU에 메모리 할당
- `cudaMemset(포인터, 값, 바이트수)` — GPU 메모리 초기화
- (`error_checking`의) `cudaMemcpy(..., DeviceToHost)` — GPU→CPU 복사

**③ 실행**: 초기화 로그를 추가로 확인하려면 `allocate_small_mem`에 출력 한 줄 추가 후 재빌드:

```c
    CUERR(MEMTEST_API_PREFIX(Malloc)((void**)&err_count, sizeof(unsigned int)));
    fprintf(stderr, "[CPU] err_count 디바이스 버퍼 할당됨 (%zu bytes)\n", sizeof(unsigned int));
```

```bash
make -j && ./cuda_memtest --disable_all --enable_test 2 --num_passes 1 2>&1 | head -5
```

**④ 관찰**: GPU가 실제 검사를 시작하기 전에 이 버퍼가 먼저 할당되는지 순서를 확인.

**⑤ 생각해보기**: `MAX_ERR_RECORD_COUNT`(=10, `tests.cpp:67`)개만 기록하는 이유는? 오류가 100만 개면
전부 저장할 수 없으니 최근 10개만 순환 기록합니다(`RECORD_ERR`의 `idx % MAX_ERR_RECORD_COUNT`).
