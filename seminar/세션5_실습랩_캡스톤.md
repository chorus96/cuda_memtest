## Part A — 멀티 GPU와 이식성 (관찰 실습)

### 큰 그림

`cuda_memtest`는 시스템의 **모든 GPU를 동시에** 검사합니다. 방법은 단순합니다:
**GPU 하나당 CPU 스레드 하나**(pthread)를 만들고, 각 스레드가 자기 GPU를 `cudaSetDevice`로 선택합니다.

```c
// main → GPU마다 pthread 생성  (cuda_memtest.cpp:543)
for (i = 0; i < num_gpus; i++){
    args[i].device = i;
    pthread_create(&pid[i], NULL, thread_func, (void*)&args[i]);
}
```

```c
// thread_func — 각 스레드가 실행  (cuda_memtest.cpp:122)
gpu_idx = device;                       // thread-local: 이 스레드의 GPU 번호
cudaGetDeviceProperties(&prop, device);
cudaSetDevice(device);                  // ★ 이 스레드는 이 GPU를 담당
allocate_small_mem();                   // 이 GPU에 오류 버퍼 할당
run_tests(ptr, tot_num_blocks);         // 이 GPU에서 모든 테스트 실행
```

`gpu_idx`는 `__thread`(스레드 지역 저장소, thread-local storage)입니다(`cuda_memtest.h:81`). 그래서 각 스레드가
**서로 다른 GPU 번호**를 헷갈리지 않고 갖습니다. 로그의 `[hostname][gpu_idx]` 접두사가 여기서 나옵니다.

### Exercise 1 — GPU마다 스레드가 뜨는 것 관찰

**① 목표**: 시스템의 각 GPU에 대해 별도 스레드가 생기고 독립적으로 검사하는 것을 로그로 확인한다.

**② 코드**: 코드 수정 없이 옵션만.

```bash
# 모든 GPU를 동시에 검사 (기본 동작)
./cuda_memtest --disable_all --enable_test 2 --num_passes 1 2>&1 | head -30

# 특정 GPU 하나만 검사
./cuda_memtest --device 0 --disable_all --enable_test 2 --num_passes 1
```

**③ 실행**: GPU가 2개 이상이면 첫 명령에서 여러 GPU 로그가 뒤섞여 나옵니다.

**④ 관찰**: 로그 접두사 `[호스트명][GPU번호]`에서 GPU 번호가 0, 1, ... 로 다른지 확인. 각 GPU가
독립적으로 "Attached to device N", "Allocated X MB"를 출력합니다.

**⑤ 생각해보기**: 왜 `gpu_idx`가 `__thread`(스레드 지역)여야 할까? 만약 일반 전역 변수라면 여러 스레드가
같은 변수를 덮어써 로그의 GPU 번호가 뒤죽박죽될 것입니다.

> GPU가 1개뿐이어도 괜찮습니다 — 스레드 1개가 생기는 구조는 동일합니다.

### Exercise 2 — 하나의 코드가 CUDA와 HIP 모두로 (이식성)

**① 목표**: `MEMTEST_API_PREFIX` 매크로가 어떻게 `cuda*`와 `hip*` 호출을 하나의 코드로 통일하는지 이해한다.

**② 코드**: 헤더의 이식성 스위치(`cuda_memtest.h:53~65`)를 읽습니다.

```c
#if defined(__CUDACC__)                              // NVIDIA CUDA 컴파일러
#    define MEMTEST_API_PREFIX(name) cuda##name      // Malloc → cudaMalloc
     using apiError_t = cudaError;
#elif defined(__HIP__)                               // AMD HIP 컴파일러
#    define MEMTEST_API_PREFIX(name) hip##name       // Malloc → hipMalloc
     using apiError_t = hipError_t;
#endif
```

그래서 코드 전체가 `MEMTEST_API_PREFIX(Malloc)`, `MEMTEST_API_PREFIX(Memcpy)`처럼 쓰여 있고,
컴파일러에 따라 `cudaMalloc` 또는 `hipMalloc`로 바뀝니다.

**③ 확인**: 소스에서 실제 사용처를 찾아보세요.

```bash
grep -n "MEMTEST_API_PREFIX(Malloc)\|MEMTEST_API_PREFIX(Memcpy)" tests.cpp | head
```

**④ 관찰**: `cudaMalloc`을 직접 쓴 곳은 거의 없고, 대부분 `MEMTEST_API_PREFIX(...)`로 감싸여 있습니다.

**⑤ 생각해보기**: `##`은 C 전처리기의 토큰 붙이기(token pasting)입니다. `cuda`와 `Malloc`을 붙여
`cudaMalloc`을 만듭니다. 이 한 줄의 매크로 덕분에 코드를 두 벌 관리하지 않아도 됩니다.

### 옵션 A 가이드 — 체커보드(checkerboard) 테스트 추가

체커보드 패턴 `0xAAAAAAAA`(1010...)와 그 보수 `0x55555555`(0101...)는 **인접 비트 간 간섭**을 잘 잡아냅니다.
좋은 소식: 이미 있는 `move_inv_test`(세션 2)를 재사용하면 됩니다!

#### 1단계 — 새 테스트 함수 작성 (`tests.cpp`)

기존 `test2`(`tests.cpp:703`) 바로 아래에 새 함수를 추가합니다.

```c
/* TestX [Checkerboard] — 0xAAAAAAAA 와 0x55555555 교차 패턴 */
void
test_checkerboard(char* ptr, unsigned int tot_num_blocks)
{
    unsigned int p1 = 0xAAAAAAAA;        // 1010...1010
    unsigned int p2 = ~p1;               // 0101...0101 = 0x55555555

    DEBUG_PRINTF("Checkerboard test, pattern 0x%x and 0x%x\n", p1, p2);
    move_inv_test(ptr, tot_num_blocks, p1, p2);   // 세션 2의 이동 반전 재사용!
    move_inv_test(ptr, tot_num_blocks, p2, p1);   // 방향 바꿔 한 번 더
}
```

> 세션 2에서 배운 `move_inv_test`가 write→readwrite→read 3커널로 검사를 다 해줍니다.
> 우리는 패턴만 정해 넘기면 됩니다. 재사용의 힘!

#### 2단계 — 테스트 등록 (`tests.cpp:1555`)

`cuda_memtests[]` 배열의 끝(Test10 뒤)에 항목을 추가합니다.

```c
cuda_memtest_t cuda_memtests[]={
    {test0,  (char*)"Test0 [Walking 1 bit]",          1},
    // ... 중략 ...
    {test10, (char*)"Test10 [Memory stress test]",    1},
    {test_checkerboard, (char*)"Test11 [Checkerboard]", 1},   // ★ 추가
};
```

구조체는 `{함수, 설명, 기본활성화}` 세 필드입니다(`cuda_memtest.h:195`).

#### 3단계 — 배열 크기 상수 고치기 (`cuda_memtest.cpp:57`) ⚠️ 중요

이 저장소는 배열 크기를 **하드코딩**해 두었습니다. 안 고치면 새 테스트가 무시됩니다.

```c
// 변경 전
extern cuda_memtest_t cuda_memtests[11];
// 변경 후
extern cuda_memtest_t cuda_memtests[12];   // 11 → 12
```

> 이것이 실전 코드의 함정입니다 — 하드코딩된 상수는 나중에 꼭 물립니다. `main`이 있는 `cuda_memtest.cpp`는
> 이 **extern 선언**에 `DIM()`(= `sizeof/sizeof`, `cuda_memtest.h:187`)을 적용해 테스트 개수를 셉니다
> (`cuda_memtest.cpp:223`). 그래서 여기가 `[11]`이면 `--list_tests`는 11개만 보여주고,
> `--enable_test 11`은 범위 초과로 거부됩니다. (`tests.cpp`의 `run_tests`는 실제 배열 정의를 보므로
> 문제없지만, 목록·활성화 로직은 이 상수에 걸립니다.)

#### 4단계 — 빌드하고 실행

```bash
make -j
./cuda_memtest --list_tests                                   # Test11이 목록에 보이는가?
./cuda_memtest --disable_all --enable_test 11 --num_passes 1   # 새 테스트만 실행
```

#### 5단계 — 검증 (세션 4 활용)

세션 2의 fault injection(읽기 커널에서 비트 훼손)을 잠시 넣어, 체커보드 테스트가 실제로 오류를
잡는지 확인하세요. 확인 후 원복.
