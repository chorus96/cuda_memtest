3. GPU 메모리 테스트 방법론(GPU Memory Test Methodology)

우리는 GPU 메모리 칩에서 두 가지 종류의 오류를 고려한다.

  1. 제조 결함 및 장기간 사용의 결과로 발생하는 영구적 하드웨어 오류(permanent hardware error)
  2. 우주 방사선(cosmic radiation)에 의해 유발되는 일시적 오류, 즉 소프트 오류(transient, or soft error)

3.1 영구적 오류 검출(Detecting permanent errors)

영구적 메모리 오류는 다양한 방식으로, 그리고 서로 다른 조건에서 나타날 수 있으며 [1], 따라서 포괄적인 검사 모음(test suite)이 필요하다. 우리는 Memtest86 유틸리티(Memtest86 utility) [5]에서 사용하는 검사 방법론을 GPU 장치 메모리(GPU device memory)에 맞게 수정하여 채택하였다. 핵심 아이디어는 메모리에 검사 패턴(test pattern)을 기록하고, 이를 다시 읽어들여 기록한 값과 동일한지 검증하는 것이다. 이 아이디어를 구현하기 위해, 우리는 앞서 언급한 기본 함수들을 실행하는 GPU 커널(GPU kernel)을 CUDA C로 각각 구현하였으며, 이들은 서로 다른 검사 패턴을 사용하여 기본 연산들의 시퀀스로 구성된 검사를 조립하는 데 사용될 수 있다.

GPU 커널은 스레드 블록(thread block)당 스레드가 1개뿐인, N×1×1 형태의 스레드 블록 그리드(grid) 위에서 실행된다. 실행되면 각 커널은 스레드당 1 MB씩, 총 N MB의 GPU 메모리를 처리한다. 전체 M MB의 GPU 메모리를 검사하기 위해, 우리는 서로 다른 초기 메모리 주소(initial memory address)를 갖는 M/N개의 커널을 실행한다. 우리의 검사에서는 M = 4,037 MB, N = 128 MB이다.

GPU 메모리 검사 프로그램은 할당 가능한 모든 GPU 메모리(M MB)를 할당하는 것으로 시작하여, 개별 검사들의 시퀀스를 실행한다. GPU 메모리에 저장된 값을 검증하는 커널 내부에서, 기대값(expected value)이 메모리에 저장된 값과 일치하지 않으면 오류 카운터(error counter)가 증가하고, 오류 주소(error address), 현재 값과 기대값, 그 밖의 유용한 정보가 저장된다. GPU 커널이 종료되면 오류 정보는 CPU 메모리로 전송되어 오류 파일(error file)에 기록된다.

이 10가지 메모리 검사는 Memtest86 유틸리티에서 사용하는 것들과 유사하며, GPU 실행에 맞게 조정되었다. 표 1(Table I)은 이 검사들에 대한 정보를 제공한다. 그림 1(Figure 1)은 8비트 패턴을 사용하는 이동 반전(moving inversion with 8-bit pattern) 검사(표 1의 3번 검사)의 예를 보여주며, 그림 2(Figure 2)는 이 검사에 사용되는 세 개의 커널 중 하나의 GPU 구현을 보여준다.

3.2 소프트 오류 검출(Detecting soft errors)

단일 방사선 이벤트는 메모리에 저장된 데이터 비트를 새로운 데이터가 기록될 때까지 손상시킬 수 있으며, 이는 소프트 오류(soft error)로 나타난다. 이러한 단일 방사선 이벤트의 주된 원인은 우주선(cosmic ray) [3]이다. 소프트 오류가 발생하는 비율은 실패까지의 시간 단위(FIT, Failures In Time)로 측정된다. 1 FIT은 소자 동작 시간 10억 시간당 소프트 오류 1건에 해당한다. 이 비율은 때때로 Mbit당 FIT(FIT per Mbit)로도 보고된다.

소프트 메모리 오류는 대부분 메모리 접근(memory access) 중에 발생하므로, 오류 발생률은 메모리 사용 강도에 비례하여 증가한다 [4]. 따라서 앞 절에서 설명한 일부 검사들도 충분히 오래 실행하면 소프트 오류를 검출하는 데 사용할 수 있다. 특히, 이동된 패턴을 사용하는 이동 반전(moving inversion with shifted pattern) 검사(6번 검사)는 오랜 기간 동안 메모리에 지속적으로 기록하고 읽어들이므로 좋은 후보이다. 그러나 하드웨어 오류 검출을 위해 설계된 검사들은 메모리 시스템에 충분한 부하를 주지 못하므로, 많은 소프트 오류를 잡아낼 가능성을 극대화하지 못한다. 따라서 우리는 메모리에 동시에 접근하는 다수의 스레드를 실행하는 GPU 커널(표 1의 10번 검사)을 구현하였다. 이 커널은 GPU 메모리에 이전에 저장해 둔 검사 패턴을 읽어 기대값과 비교한 뒤, 그 보수(비트 반전 값, complement)를 메모리에 다시 기록한다. 오류가 발견되면 해당 메모리를 한 번 더 읽어 두 개의 읽기 값을 보고한다. 검사 패턴은 난수(random number)이다. 이 커널은 무한 루프(infinite loop)로 실행되며, 새로운 검사 패턴으로 넘어가기 전에 동일한 검사 패턴을 1,000회 사용한다.
