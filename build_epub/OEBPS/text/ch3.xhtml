4. 실험 결과(Experimental Results)

실험을 위해 우리는 NVIDIA Tesla S1070 GPU 가속기(GPU accelerator)가 장착된 두 개의 클러스터를 사용하였다. QP 클러스터(QP cluster) [8]의 확장 버전인 AC는 노드 32개와 노드당 GPU 4개로 구성된 AMD 기반의 연구용 클러스터이다. Lincoln은 노드 192개와 노드당 GPU 2개(Tesla 96대, 각각 두 노드가 공유)로 구성된 Intel 기반의 생산용 클러스터이다.

우리는 GPU 메모리 검사를, 새로운 하드웨어 결함이 나타나는지 시스템을 지속적으로 모니터링하고 소프트 오류 발생률에 관한 통계를 수집하는 데 사용하는 유틸리티로 구상하고 있다. 이 목표를 달성하기 위해, AC에서는 시스템이 달리 유휴 상태(idle)였을 모든 가용 시간 동안 GPU 메모리 검사를 실행하였다. 이를 용이하게 하기 위해, 배치 시스템 및 스케줄러(각각 Torque와 Moab)를 선점 가능한 작업(preemptible job)을 허용하도록 구성하였다. 기본적으로 제출되는 작업은 선점자(preemptor)가 된다. GPU 메모리 검사 작업은 선점 대상(preemptee) 플래그를 붙여 제출되어, 일반 작업이 제출되면 취소되었다가 자원이 가용해질 때 다시 시작되도록 하였다. 각 노드에 대해 해당 노드를 특정한 별도의 memtest 작업이 생성된다. 오류가 검출되면 그 작업은 알림 이메일을 보내고 검사를 계속한다.

Lincoln에서는 하드웨어 결함 검출을 위한 모든 검사를 수행하기에 충분한 기간 동안 GPU 메모리 검사를 일반 작업으로 실행하였다. 우리는 아직 Lincoln에서 소프트 오류에 관한 통계를 수집하려는 시도는 하지 않았다.

4.1 소프트 오류(Soft errors)

현대의 메모리 소자는 Mbit당 1,000–5,000 FIT의 오류율, 즉 메모리 1 GB당 대략 한 달에 1비트 오류 정도의 오류율을 갖는 것으로 여겨진다 [2]. 따라서 우리는 수천만 FIT 수준의 오류율, 즉 지속적으로 동작하는 GPU 카드 1장당 한 달에 4비트 오류 정도를 예상해야 한다. 우리는 소프트 오류 메모리 검사(10번 검사)를 두 번 독립적으로 수행하였다.

  1. 15일 기간 동안 AC 클러스터 노드들이 사용되지 않을 때, 약 4 GB 메모리 기준으로 총 7,222시간의 운영 시간을 합산한 실행.
  2. 이 검사만을 전담으로 수행한 15개 AC 클러스터 노드에서, 약 4 GB 메모리 기준으로 총 10,080시간의 운영 시간을 합산한 실행.

그러나 이 두 검사 어느 쪽에서도 소프트 오류는 검출되지 않았다. 이는 우리의 검사 방법론이 올바르지 않거나, 또는 소프트 오류가 다른 연구들이 제시한 것보다 훨씬 드물게 발생한다는 것을 시사한다.

4.2 영구적 오류(Permanent errors)

영구적 하드웨어 결함을 검출하기 위해 GPU 메모리 검사를 한 번 통과(single pass)하려면(0–9번 검사) 10가지 검사를 모두 실행하는 데 거의 3시간 반이 걸린다. 비트 페이드 검사(bit fade test, 9번 검사)가 3시간으로 가장 시간이 오래 걸린다. 이 검사는 오랜 기간에 걸친 데이터 보존(data retention) 문제로 인한 오류만을 잡아내도록 설계되었으므로, 우리는 이를 정기 검사(routine test)의 일부로는 실행하지 않는다. 나머지 모든 검사를 합치면 27.8분이 소요되며, 그중 시프트 패턴 이동 반전 검사(6번 검사)가 약 23.5분으로 대부분의 시간을 차지한다. 0–8번 검사가 끝나면, 뒤에서 설명하듯이 일부 갑작스러운 하드웨어 오류를 찾아내는 데 결정적인 역할을 한 10번 검사도 실행한다. 메모리 오류가 있는 노드가 발견되면, 우리는 그 노드를 재부팅하고 동일한 검사를 수행하여 우리의 발견을 확인한다.

우리는 AC 클러스터에서 128개 중 4개의 GPU 카드를, Lincoln 클러스터에서 검사한 378개 중 5개의 GPU 카드를, 우리의 검사 방법론으로 일관되게 재현할 수 있는 결함 메모리를 가진 카드로 식별할 수 있었다. 아래에 AC 클러스터에서 발견된 오류들을 나열한다.

  • 노드 3, GPU 3(Node 3, GPU 3): 검사 1, 5–8, 10번이 검사 시작 후 수 분 이내에 실패하며, 서로 다른 메모리 주소에 대해 많은 오류를 보고한다.
  • 노드 5, GPU 1(Node 5, GPU 1): 검사 6번과 10번이 24시간 기간당 몇 차례 실패한다. 오류는 서로 다른 메모리 주소에서 검출된다. 10번 검사는 소프트 오류의 특징이라 할 수 있는 단일 비트 뒤집힘(single bit flip)을 보고한다. 그러나 동일한 Tesla 유닛에 속한 다른 GPU 노드들에서는 유사한 오류가 보고되지 않는 점에 비추어, 우리는 이것이 소프트 오류라고 생각하지 않는다.
  • 노드 25, GPU 1(Node 25, GPU 1): 검사 6번과 10번이 몇 시간 이내에 실패한다. 오류는 서로 다른 메모리 주소에서 검출된다. 앞의 노드와 대조적으로, 10번 검사는 소프트 오류의 특징이 아닌 오류를 보고한다. 10번 검사는 메모리에 난수 값을 기록한 뒤 이를 두 번 다시 읽는데, 첫 번째 읽기에서 반환된 값은 무작위 비트 하나가 뒤집혀 있으나 두 번째 읽기에서 반환된 값은 올바르다.
  • 노드 28, GPU 1(Node 28, GPU 1): 검사 1–4, 6, 10번이 실행 후 몇 시간 이내에 동일한 메모리 주소(0xe7fbc990)에서 발생하는 단일 비트 뒤집힘 오류를 보고한다. 이 오류는 단일 비트(비트 6번)가 ‘1’에 고착(stuck-at ‘1’)된 것으로 보인다.

이 논문을 작업하는 동안, 우리는 스탠퍼드(Stanford)에서 개발 중인 MemtestG80 [7]이라는 유사한 GPU 메모리 검사 소프트웨어를 발견하였다. 이 스탠퍼드 코드를 사용하여, 우리는 4개 노드 중 3개 노드에서 메모리 오류를 확인할 수 있었으며, 노드 5, GPU 1에서는 오류를 확인할 수 없었다.

NVIDIA는 우리 클러스터에 있던 일부 Tesla 유닛이 제조 검사를 제대로 거치지 않아 불량 메모리를 가지고 있었을 가능성이 있다고 확인해 주었다.

일부 검사는 무작위로 생성된 검사 패턴을 사용하므로, 잘못된 응답을 유발할 수 있는 검사 패턴이 특정 검사 실행에서는 나타나지 않을 위험이 있다. 그러나 우리는 오류가 한 번 검출되면 짧게는 3분마다, 길게는 최대 20시간 간격의 빈도로 반복해서 나타난다는 점을 확인하였다. 주목할 점은, 서로 다른 GPU들은 서로 다른 검사에서 오류가 나타났지만, 특정 GPU는 항상 동일한 검사 내에서 일관되게 실패했다는 것이다. 또한 어떤 검사도 첫 번째 통과에서 반드시 실패하지는 않았다.
